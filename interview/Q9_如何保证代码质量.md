## 🔍 常见追问

### Q: 为什么选择 sqlmock 而不是真实数据库？

**答**：
使用 sqlmock 有几个优势：

1. **速度快**：不需要启动真实数据库，测试执行速度快
2. **隔离性好**：每个测试独立，不会相互影响
3. **易于控制**：可以精确控制数据库返回结果
4. **CI/CD 友好**：不需要在 CI 环境配置数据库

当然，我们也会进行集成测试，使用真实数据库验证完整流程。

### Q: 测试覆盖率 60% 是否太低？

**答**：
60% 的覆盖率是一个合理的平衡点：

1. **核心逻辑 100% 覆盖**：业务核心逻辑（如库存扣减、订单创建）都有完整测试
2. **性价比考虑**：追求 100% 覆盖率成本很高，边际收益递减
3. **重点突出**：我们重点测试复杂逻辑和容易出错的地方
4. **持续改进**：随着项目发展，覆盖率会逐步提升

### Q: 如何测试并发场景？

**答**：
我们使用多种方法测试并发：

```go

            defer wg.Done()

            doSomething(id)
        }(i)
    }
    
    wg.Wait()
    // 验证结果
}
```

### Q: 测试失败了怎么办？

**答**：
我们有完整的失败处理流程：

1. **立即定位**：查看测试日志，定位失败原因
2. **本地复现**：在本地环境复现问题
3. **修复问题**：修复代码或测试用例
4. **回归测试**：确保修复后所有测试通过
5. **总结经验**：分析失败原因，避免类似问题

### Q: 如何保证测试的质量？

**答**：
测试本身也需要保证质量：

1. **测试要简单**：每个测试只测一个功能点
2. **测试要独立**：测试之间不能相互依赖
3. **测试要快速**：单个测试应该在秒级完成
4. **测试要稳定**：不能有随机失败（flaky test）
5. **测试要有意义**：不写无意义的测试

## 💻 代码示例

### 完整的测试示例

```go
package data

import (
    "context"
    "testing"
    
    "github.com/DATA-DOG/go-sqlmock"
    "github.com/stretchr/testify/assert"
    "gorm.io/driver/mysql"
    "gorm.io/gorm"
)

// 测试库存扣减
func TestDeductInventory(t *testing.T) {
    // 1. 准备 Mock 数据库
    db, mock, err := sqlmock.New()
    assert.NoError(t, err)
    defer db.Close()
    
    gormDB, err := gorm.Open(mysql.New(mysql.Config{
        Conn: db,
        SkipInitializeWithVersion: true,
    }), &gorm.Config{})
    assert.NoError(t, err)
    
    // 2. 创建 repo
    repo := &inventoryRepo{
        data: &Data{db: gormDB},
    }
    
    // 3. Mock 查询库存
    rows := mock.NewRows([]string{"id", "goods", "stocks"}).
        AddRow(1, 100, 10)
    mock.ExpectQuery("SELECT .* FROM `inventory`").
        WithArgs(100).
        WillReturnRows(rows)
    
    // 4. Mock 更新库存
    mock.ExpectBegin()
    mock.ExpectExec("UPDATE `inventory`").
        WithArgs(7, 1).
        WillReturnResult(sqlmock.NewResult(1, 1))
    mock.ExpectCommit()
    
    // 5. 执行测试
    err = repo.Deduct(context.Background(), 100, 3)
    
    // 6. 验证结果
    assert.NoError(t, err)
    assert.NoError(t, mock.ExpectationsWereMet())
}

// 测试并发扣减
func TestConcurrentDeduct(t *testing.T) {
    const goroutines = 100
    const deductNum = 1
    
    var wg sync.WaitGroup
    errors := make(chan error, goroutines)
    
    // 并发扣减
    for i := 0; i < goroutines; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            err := repo.Deduct(ctx, goodsId, deductNum)
            if err != nil {
                errors <- err
            }
        }()
    }
    
    wg.Wait()
    close(errors)
    
    // 验证没有错误
    for err := range errors {
        t.Errorf("Deduct failed: %v", err)
    }
    
    // 验证最终库存
    inventory, err := repo.Get(ctx, goodsId)
    assert.NoError(t, err)
    assert.Equal(t, initialStock-goroutines*deductNum, inventory.Stocks)
}
```

## 📚 相关知识点

### 测试金字塔

```
       /\
      /  \  E2E 测试 (10%)
     /────\
    /      \ 集成测试 (20%)
   /────────\
  /          \ 单元测试 (70%)
 /────────────\
```

### 测试原则

1. **FIRST 原则**：
   - Fast（快速）
   - Independent（独立）
   - Repeatable（可重复）
   - Self-Validating（自我验证）
   - Timely（及时）

2. **AAA 模式**：
   - Arrange（准备）
   - Act（执行）
   - Assert（断言）

### 测试类型

- **单元测试**：测试单个函数或方法
- **集成测试**：测试多个组件协作
- **端到端测试**：测试完整业务流程
- **性能测试**：测试系统性能
- **压力测试**：测试系统极限
