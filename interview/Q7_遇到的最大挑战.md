# Q7: 遇到的最大挑战？

## 🎯 回答框架（2-3分钟）

最大的挑战是实现 **订单超时自动取消** 功能。

## 1. 业务需求

用户下单后 30 分钟内未支付，系统需要：
- ✅ 自动取消订单
- ✅ 归还库存
- ✅ 通知用户
- ✅ 记录日志

## 2. 方案对比

| 方案 | 性能 | 可靠性 | 问题 |
|------|------|--------|------|
| **定时任务轮询** | 差 | 中 | 延迟高、资源浪费 |
| **时间轮** | 好 | 差 | 服务重启丢失 |
| **延迟消息** | 好 | 高 | 需要消息队列 ✅ |

## 3. 最终方案：RocketMQ 延迟消息

### 3.1 实现代码

```go
// 创建订单时发送延迟消息
func (s *OrderService) CreateOrder(ctx context.Context, req *OrderRequest) error {
    // 1. 创建订单
    order := &Order{
        OrderSn: generateOrderSn(),
        Status:  "UNPAID",
    }
    db.Create(order)
    
    // 2. 发送 30 分钟延迟消息
    msg := &primitive.Message{
        Topic: "order_timeout_topic",
        Body:  []byte(order.OrderSn),
    }
    msg.WithDelayTimeLevel(16)  // 30分钟
    
    producer.SendSync(ctx, msg)
    return nil
}

// 消费延迟消息
func (s *OrderService) ConsumeTimeoutMessage(msgs []*primitive.MessageExt) {
    for _, msg := range msgs {
        orderSn := string(msg.Body)
        
        // 查询订单状态
        order := getOrder(orderSn)
        
        // 如果仍未支付，取消订单
        if order.Status == "UNPAID" {
            order.Status = "CANCELLED"
            db.Save(order)
            
            // 归还库存
            sendReturnInventoryMessage(order)
            
            // 通知用户
            notifyUser(order)
        }
    }
}
```

### 3.2 方案优势

- ✅ **精准定时**：延迟误差小于1秒
- ✅ **高性能**：无需轮询数据库
- ✅ **可靠性高**：消息持久化
- ✅ **支持分布式**：多消费者负载均衡

## 💡 面试回答模板

"最大的挑战是订单超时自动取消功能。

**问题**：用户下单后30分钟未支付需要自动取消。

**难点**：
1. 定时任务轮询性能差，每分钟扫描数据库
2. 时间轮方案服务重启后定时器丢失
3. 需要支持分布式，多个服务实例

**解决方案**：使用 RocketMQ 延迟消息
- 创建订单时发送30分钟延迟消息
- 消息持久化到磁盘，服务重启不丢失
- 30分钟后消费消息，检查订单状态
- 如果未支付则取消订单并归还库存

**效果**：
- 延迟精度从分钟级提升到秒级
- 无需轮询数据库，性能提升10倍
- 支持分布式，可靠性高

**降级方案**：如果 RocketMQ 不可用，降级到定时任务兜底。"
